# 2026.241.1503 — fix(service): the running probe fails for a supervisord program in FATAL state (#456)

## Summary

The `service:` running probe was `supervisorctl status <svc> | grep -q RUNNING || systemctl is-active --quiet <svc>` — a bare grep plus a systemctl fallback. For a program in a TERMINAL state (FATAL/BACKOFF/EXITED — supervisord gave up or is not running), the grep fails and the probe falls through to `systemctl is-active`, which reports the WRAPPED LAUNCHER unit as "active" even when the supervisord child is dead — a vacuous pass (opencharly/charly#456).

The probe now parses the ACTUAL supervisorctl state: RUNNING/STARTING pass the running check (STARTING is a transient), FATAL/BACKOFF/EXITED FAIL, and only a program supervisorctl does not know at all falls back to systemd. The enabled probe gets the same treatment.
