# 2026.242.2146 — feat(service): scope: user, and none_failed — the two systemd questions with no verb

## Summary

`#ServiceInput` was `{service, running, enabled}` and the probe asked the **system** manager
unconditionally. Two ordinary assertions therefore had no typed form:

```sh
systemctl --user is-active pipewire.service      # a session service
systemctl --failed --no-legend                   # nothing is broken
```

The first is not a corner case: the repo works around it in **85 places** today, all
`systemctl --user` inside `command:` bodies.

## `scope: system | user`

Adds `--user` to the probe. Defaults to today's behaviour, so every existing step is
unchanged.

`scope: user` also **skips the supervisorctl leg** rather than falling through it.
supervisord has no user scope, so consulting it for a user unit finds nothing and falls
through to systemd — the right answer by accident. It would be the wrong answer if a
supervisord program happened to share the unit's name, which on a desktop pod running both
is not far-fetched.

## `none_failed: true`

"No unit is in the failed state" — the strongest whole-machine assertion available, and one
with no per-unit spelling. Every other assertion this verb makes names a unit, and the value
of this one is precisely that it names none: the unit that breaks a machine is the one
nobody thought to write a check for.

`ignore:` takes a regex for units expected to fail on a given host (a fingerprint reader
with no hardware, a vendor agent with no licence). Opt-in and per-step rather than a
built-in allowlist somebody would grow forever; a fresh VM should need none.

It lives on `service:` rather than in a new verb because it is the same subject reached
through the same executor — a second systemd verb would be two implementations of "ask the
init system" (R3). `service:` becomes optional to make room for it, and the two shapes are
mutually exclusive: a step naming a unit AND sweeping every unit would give one verdict for
two questions, so that is refused with a message naming both shapes. A step setting neither
is refused too, since an empty step became syntactically possible.

## The failure-open bug this shipped with, and how it was caught

The first revision disambiguated "empty output, non-zero exit" by asking `is-system-running`
and treating only `exit == 127` as unreachable. Running it against a real container proved
that wrong:

```
$ systemctl --failed --no-legend --plain
System has not been booted with systemd as init system (PID 1). Can't operate.
Failed to connect to system scope bus via local transport: Host is down
exit=1                          <- and STDOUT IS EMPTY

$ systemctl is-system-running
offline
exit=1
```

`offline` exits **1**, not 127. The manager was classified "reachable but degraded" and the
sweep reported `PASS no failed system units` **on a machine with no systemd at all** — the
exact failure-open this code exists to prevent. The unit test missed it because it invented
exit 127 instead of measuring what systemctl does.

The fix reads the **state**, not the exit code: `is-system-running` exits non-zero for
`degraded`, `starting` and `maintenance`, all live managers; only `offline`, `unknown` and
no answer at all mean the question could not be asked. The three tests now carry the
measured values with the observed transcript in a comment.

This is the strongest argument for the change as a whole: the reason `none_failed` needs to
exist is that silence is not evidence, and the first draft was itself an instance of that.

## How tested

Full suite, uncached, complete output:

```
$ go test -count=1 ./...
ok  	github.com/opencharly/plugin-service/candy/plugin-service	0.011s

?   	github.com/opencharly/plugin-service/candy/plugin-service/params	[no test files]

```

Eleven tests: a clean machine passes; the failure names every offender and the count;
`ignore:` excludes; an unparseable `ignore:` fails loudly; **the unreachable manager fails**
(`offline`, `unknown`, and no-answer, all measured); a reachable-but-`degraded` manager still
counts as a genuine pass; user scope reports which manager it swept; and both refusals.

**Live**, through `charly check box` against a real Arch container (which has the systemctl
binary but no running systemd) on a charly built with a local `replace` onto this branch —
before the fix:

```
PASS  check no failed system units — a container has no systemd to ask
      [probe-none-failed-unreachable]  no failed system units          <- WRONG
```

and after:

```
FAIL  check no failed system units — a container has no systemd to ask
      [probe-none-failed-unreachable]
      none_failed: cannot reach the system systemd manager (is-system-running: offline)
      — `systemctl --failed` exited 1 with no output, which is NOT the same as
      'nothing failed'
```

`params/cue_types_gen.go` was regenerated with the real toolchain, not hand-edited:
`cue exp gengotypes` in a temp module headed `@go(params)` / `package params`, then
`spec/internal/schemagen -mode=retag` — the same two-step `task cue:gen` runs in `spec`.
Diffed against the committed file: the only deltas are the three new fields and `Service`
gaining `omitempty`, which is the intended consequence of making it optional.

## Rulebook compliance

- **R1 — RCA every anomaly.** The vacuous pass was root-caused to reading an exit code
  instead of a state, measured against real systemctl output, and fixed — not allowlisted.
- **R3 — No duplication.** The sweep extends the existing `service` verb rather than adding
  a second systemd verb.
- **R4 — No workarounds.** No sleeps, no blind retries; the ambiguous case is disambiguated
  by asking a second, unambiguous question.
- **R4a — Fix the product first.** The consuming beds convert only once this ships.
- **R5 — Delete legacy completely.** N/A — additive; `scope:` defaults to today's behaviour.
- **R6 — Git safety.** `git status` inspected; branched from a fresh `origin/main`; no
  force-push, no direct push to `main`, no hook bypass.
- **R7 — Prove the gate, not the plan.** Complete uncached suite plus the before/after live
  transcript of the failure-open case.
- **R9 — Binary equals source.** Both live runs are from `task build:binary` charly builds
  carrying the respective revisions of this branch.
- **R10 — Fresh disposable proof.** `charly check box` runs in a `podman run --rm`
  disposable container, built fresh for each run.
